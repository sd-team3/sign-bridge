# 수어 단어 시험과 코칭 화면

`/exam/setup`과 `/exam/words`에서 기본 70단어 시험을 제공한다. 기존 지문자·사전 퀴즈 시험은 `/exam/legacy/setup`에서 유지한다.

## 시험

- 챕터 시험: 해당 챕터 10단어를 중복 없이 출제한다.
- 종합 시험: 7개 챕터에서 각 2단어, 총 14문항을 출제한다.
- 영상 이해, 동작 표현, 두 유형 혼합 중 선택한다. 혼합은 이해·표현을 번갈아 출제한다.
- 오답·판정 보류 복습은 종료한 본인의 시험에서 최대 10단어를 추출한다.
- 출제 대상과 모범 영상은 Python의 기본70 카탈로그에서 가져온다. 기존 사전 DB의 임의 단어와 이름으로 연결하지 않는다.
- 녹화는 음성 없이 2~19초, 최대 25MiB, WebM/MP4로 제출한다. 제출 전 미리보기와 재촬영을 제공한다. 서버 영상 제한은 기존 `/evaluate-video`를 따른다.
- 불확실한 동작은 판정 보류로 저장하며 최대 3번 평가할 수 있다. 평가 요청 실패는 횟수를 차감하지 않는다. 보류로 넘긴 뒤에도 새로고침으로 진행 상황을 복구할 수 있다.
- 정답과 자세 코칭은 종료 후 공개한다. 영상 이해 정답은 서버에 보관하고, 문제 영상은 문제 번호로 중계한다.
- 이해 점수와 표현 결과를 분리한다. 보류 문제가 있으면 평가 미완료로 표시한다. 이해 문제에 보류가 있으면 이해 점수도 계산하지 않는다.
- 표현 결과는 AI 학습용 평가다. 최상위 단어 인식 확률이 0.7 이상일 때 목표 단어 여부를 사용한다. 손 검출·비교 부족, 시범 없음, 불확실한 분류는 판정 보류다. 동작 유사도 70은 코칭 기준이며 시험 합격 기준으로 사용하지 않는다. 이 기준은 실제 사용자 웹캠으로 별도 검증해야 한다.
- 새 시험은 포인트·합격 판정을 지급하지 않는다. 기존 지문자 시험의 포인트 정책은 변경하지 않는다.

## 저장과 배포

새 `word_exam` 테이블에 응시자와 시험 JSON을 저장한다. 출제 당시 단어·보기·정답, 커리큘럼 버전, 채점 정책 버전, 평가 모델 ID와 문항별 평가 결과를 보존한다. 원본 녹화 영상은 DB에 저장하지 않는다.

Spring 시작 시 `db/word-exam.sql`의 `CREATE TABLE IF NOT EXISTS`를 실행한다. 기존 테이블과 기록은 수정하지 않는다. DB 계정에 CREATE 권한이 없다면 관리자가 SQL을 먼저 실행하고 `app.properties`에 `word.exam.initialize-schema=false`를 설정한다. DB 변경 권한 정책상 자동 초기화를 사용하지 않는 환경에서도 같은 설정을 사용한다.

Spring을 다시 빌드·시작해야 새 Java 클래스와 DB 리소스가 반영된다. Python은 기본70 모델과 `/api/v1/signs/chapters`, `/evaluate-video`, `/reference/{word_id}`가 준비되어 있어야 한다. 시험 도중 모델 ID가 바뀌면 기존 기록에 섞어 저장하지 않고 새 시험을 안내한다.

DB 행 잠금과 트랜잭션으로 제출·종료를 직렬화한다. 응시자 소유권을 모든 시험 요청과 영상 요청에서 확인한다. 중복 답안과 완료한 평가의 재제출은 기존 결과를 유지한다. 같은 촬영 ID의 재요청은 중복 평가하지 않는다. 새 API는 기존 `/exam/api/**`의 CSRF 예외 경로 밖에 있으며 CSRF 헤더를 전송한다.

## API

모든 경로는 `/exam/words/api` 하위다. 로그인한 본인 기록만 접근할 수 있다.

| 메서드 | 경로 | 요청 |
|---|---|---|
| POST | `/start` | mode=choice/motion/both, chapter=chapter-01 등 또는 빈 문자열, review=복습할 시험 ID 또는 빈 문자열 |
| GET | `/history` | 최근 20개 시험 |
| GET | `/{id}` | 진행 상황 또는 종료 결과 |
| GET | `/{id}/questions/{number}/video` | 문제 영상, Range 지원. 표현 문제는 종료 후 허용 |
| POST | `/{id}/choice` | number, answer=보기 ID |
| POST | `/{id}/motion` | multipart: number, attempt_id, video |
| POST | `/{id}/skip` | number |
| POST | `/{id}/finish` | 서버가 저장된 답안에서 결과 집계 |

문제 번호는 0부터 시작한다. 클라이언트의 isCorrect, correctCount, passScore는 받지 않는다.

## 코칭 화면

학습과 시험 결과에 같은 코칭 컴포넌트를 사용한다. 핵심 제목과 첫 번째 교정만 기본 표시하고 나머지는 '추가 연습 포인트' 안에 접어 둔다. 중복 문구를 제거하고 측정 불가와 동작 비교 점수를 구분한다. 낮은 점수나 검출 부족 안내가 단순 칭찬으로 가려지지 않게 한다. 모델의 원래 actions와 observations는 변경하지 않는다.

## 학습 자동 녹화와 메뉴

단어 학습에서 카메라를 켜면 손 감지를 준비하고, 한 손 이상이 약 0.15초 감지될 때 자동 녹화한다. 녹화 중에는 초록 테두리와 녹화 표시를 보여 준다. 양손 모두 약 0.9초 동안 감지되지 않고 녹화 시간이 2초 이상이면 자동 종료하고 평가한다. 한 손이 남아 있거나 잠깐 가려지는 경우에는 종료하지 않는다. 최대 19초 제한은 유지하며, 다음 녹화는 손이 화면에서 0.6초 이상 사라진 뒤 다시 나타나야 시작한다. 탭을 숨기거나 카메라 연결이 끊긴 촬영은 평가에 사용하지 않는다. 평가 요청 실패 시 같은 영상 재평가를 제공한다.

손 감지는 별도 Web Worker에서 MediaPipe Hand Landmarker 0.10.14로 수행한다. 한 번에 최대 두 손을 확인하고, 최대 약 10fps·가로 480px으로 처리한다. 모델과 WASM은 기존 지문자 카메라와 같은 MediaPipe 배포 경로에서 최초 로드하므로 네트워크 접근이 필요하다. 실시간 손 감지 프레임은 서버에 전송하지 않고, 종료한 녹화 영상만 기존 평가 API로 전송한다. 시험의 수동 녹화·미리보기·제출 방식은 유지한다.

헤더의 시험 메뉴는 마우스를 올리거나 클릭하면 지문자 시험과 수어 단어 시험을 선택할 수 있다. 터치와 키보드는 기존 details 메뉴 방식으로 이용한다. 수어 단어 시험 안의 기존 시험 이동 버튼은 제거했다. 판정 보류의 내부 상태와 채점 정책은 유지하고 화면에서는 '확인 필요', '이 문제는 나중에 연습할게요' 등으로 안내한다.

## 검증

Windows에서 `powershell -ExecutionPolicy Bypass -File tests/run-word-exam-tests.ps1`로 실행한다. 기존 `target/classes`와 `target/dependency`가 필요하다. 테스트용 H2와 jsdom은 임시 폴더에 설치한다.

H2의 MySQL 호환 모드에서 실제 MyBatis 매퍼·SQL·트랜잭션을 사용해 출제, 소유권, 정답 비공개, 서버 채점, 보류, 중복 제출, 복습, 모델 변경과 결과 저장을 검사한다. jsdom에서 실제 JSP 구조와 JS를 실행해 선택·녹화·미리보기·보류·종료·코칭 표시를 검사한다. 이 테스트의 카메라와 분석 응답은 테스트 대역이다.

2026-11-03 Docker 개발 환경에서 Maven 빌드와 Tomcat 시작, 실제 MySQL 테이블 생성을 확인했다. 임시 테스트 계정으로 Brave에서 영상 이해 시험 10문항 제출·종료·결과 복원과 모바일 화면을 확인했다. 실제 모범 영상을 640×360 MP4로 변환해 Spring의 시험 업로드 API로 제출했고 Python `curriculum70_seated_v3` 분석·정답 판정·MySQL 저장을 확인했다. 비로그인 요청 401, CSRF 없는 제출 403도 확인했다. 테스트 계정 1개와 시험 기록 2개는 검증 후 삭제했다. 실제 사용자의 물리 웹캠 촬영은 별도 확인이 필요하다.

자동 녹화 변경은 Brave의 가상 웹캠에 검은 화면·실제 수어 영상·검은 화면을 순서대로 입력해 검사했다. 실제 Web Worker·MediaPipe 모델로 손을 감지하고, 버튼 입력 없이 녹화 시작·초록 테두리·종료·Spring/Python 평가·코칭 표시까지 확인했다. 시험에 수동 녹화 버튼이 남아 있는지와 시험 헤더 hover 메뉴도 확인했다.
