# 학습 동작 비교 아바타와 진단 기록

학습 페이지에서 평가를 마치면 결과 카드의 **모범 · 내 동작을 아바타로 비교하기**를 펼칠 수 있다. 초반·중간·후반을 선택하고 크게 볼 수 있다. 인식 확인이 필요한 결과에서는 비교 영역을 자동으로 펼친다.

## 비교의 의미

상체와 손의 측정 좌표를 두께 있는 2D 아바타로 그린다. 모범과 사용자를 같은 어깨 기준으로 정규화하고, 손 모양은 따로 확대한다. 사진 복원이나 실제 피부·얼굴을 생성하는 기능은 아니다. 양쪽은 정면 영상 방향이며 카메라의 거울 미리보기와 다를 수 있다.

평가에 선택된 REAL01~03 시범과 좌우 반전 상태를 사용한다. 손 위치·관절 각도 DTW로 구간을 정렬하고 각 영상의 시각을 표시한다. 정렬 근거가 약하면 상대 진행 시점으로 표시하고 차이 강조를 생략한다. 손·어깨가 검출되지 않은 부분은 임의로 복원하지 않는다.

충분한 관측과 일관된 측정 차이가 있는 손 위치·손가락만 노란색으로 표시한다. 표시는 관측 차이이며 반드시 고쳐야 하는 오류를 뜻하지 않는다. 기존 인식 중심 코칭을 유지하며 좌표 차이를 정답 판정으로 사용하지 않는다. 비교 이미지 생성에 실패해도 단어 인식 결과는 유지한다.

## API와 Spring

`POST /api/v1/signs/evaluate-video`의 multipart `include_comparison`은 기본 false다. true이면 `feedback.comparison`에 다음을 추가한다.

- `available`, `kind=coordinate_avatar_v1`
- `alignment=dtw` 또는 `relative_time`, `notice`
- `reference_subject`, `mirrored_reference`
- `frames`: phase, reference_timestamp_ms, user_timestamp_ms, image

image는 외부 URL이 없는 자체 SVG의 data URL이다. 브라우저는 img로 표시하며 SVG를 HTML로 삽입하지 않는다. Spring 학습 중계는 true, 시험 중계는 false를 보내므로 시험 저장 결과에 큰 이미지 묶음을 넣지 않는다. 시험의 수동 녹화·채점 방식은 유지한다.

모범 영상의 원시 손·상체 좌표 캐시는 `data/comparison_cache`에 저장한다. 시범 210개를 사전 생성했고, 원본 영상 해시와 캐시 버전으로 유효성을 확인한다. 이 경로는 Git에서 제외한다.

## 진단 자료

새 영상 평가부터 `data/practice_diagnostics/YYYY-MM-DD`에 동작 좌표 NPZ와 결과 JSON을 저장한다. 이 경로는 웹 정적 파일로 공개하지 않고 Git에서도 제외한다. 원본 업로드 영상은 계속 분석 후 삭제한다.

기록에는 손·Pose 좌표, 타임스탬프, 화면 비율, 모델 ID, 목표 단어, 상위 후보·확률·수락 여부, 검출 상태와 비교 정렬 방식을 포함한다. `verified_label=null`, `annotation_status=unreviewed`로 기록하며 목표 단어를 자동 정답 라벨로 사용하지 않는다. 테스트로 생성한 시도는 별도로 표시한다. 원시 좌표를 이용하면 이전 입력을 재생하고 모델·전처리 변경을 비교할 수 있다. `SIGN_SAVE_PRACTICE_COORDS=false`로 새 좌표 저장을 끌 수 있다.

## 입력 처리 수정

24fps에서 round(fps/15) 간격으로 추출하면 실제로 초당 12프레임만 분석하던 문제를 수정했다. FPS가 있거나 타임스탬프로 복원하는 경우 모두 시간 격자를 기준으로 약 15fps를 추출한다. 24fps 2초 영상에서 기존 24개 대신 30개를 분석하는 회귀 검사를 추가했다. 20초·해상도·25MiB 제한은 유지한다.

## 모델 실험

실사용 로그에서 짧은 손 검출 구간이 관측되어 기존 v5 문맥 모델을 낮은 시간 해상도(14~32프레임) 증강으로 추가 학습했다. 사용자 시도는 검증된 정답이 없고 과거 원본이 남지 않아 학습에 사용하지 않았다.

분리 인물 REAL13~14 평가에서 후보 v6는 원본 정답 137→138/140, 16프레임 입력 정답 135→136/140으로 변했다. 16프레임의 확신한 오인식은 3→1로 줄었지만 원본의 확신한 오인식이 1→2로 늘었다. 따라서 현재 서비스 가중치는 v5를 유지한다. 이 평가 인물은 과거 프로젝트에서도 평가했던 인물이며 실제 노트북 동작에 대한 성능 보장은 아니다. 임계값을 낮추거나 평가 결과를 보고 재학습하지 않았다.

실험 기록: `D:/sign-lang/artifacts/curriculum70_webcam_v6/v5_comparison.json`.

## 검증

Python 단위·회귀 검사, Spring·DB 검사, 화면의 구간 선택·확대·안전한 이미지 처리·오래된 팝업 정리 검사를 수행했다. 실제 Docker Spring→Python 경로와 가상 웹캠에서 자동 녹화→인식→비교 이미지 표시를 확인했다. 모바일 가로 넘침도 검사했다. 실제 사용자 동작의 정확한 교정 여부는 전문가 확인과 추가 자료가 필요하다.

### 노란 표시 설명

`comparison.frames[].highlight_notes`는 해당 이미지에 실제로 노랗게 표시한 손 위치·손가락의 설명 배열이다. `comparison_status`는 `highlighted`, `no_major_difference`, `unavailable` 중 하나다. 참고 영역은 선택한 초반·중간·후반 이미지의 설명만 표시한다. 표시가 없고 비교 가능한 경우에는 큰 차이를 찾지 못했다고 안내하며, 검출·정렬 불충분은 별도로 안내한다. 단어 인식·시험 판정은 변경하지 않는다.
