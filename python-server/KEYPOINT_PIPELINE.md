> 현재 운영 상태: 사용자 요청으로 v8 테스트 적용. 인식·시험 판정은 v8 가중치와 hands_tracking_v2 전처리를 사용한다. 아래 배포 보류 설명은 이전 자동 검증 당시의 기록이며, 평가 결과 자체는 변경하지 않았다. v5 복구본을 별도 보존했다.

# 수어 좌표 추출·학습 점검

현재 작업의 결과 수치는 `data/curriculum100_tracking_v2/audit.json`,
`artifacts/curriculum70_tracking_v7/v5_comparison.json`,
`artifacts/curriculum70_tracking_v8/v5_comparison.json`에서 확인한다.
배포 여부와 실제 모델 해시는 `tmp/tracking_deployment.json`에 기록한다.

## 확인한 원인

- 기존 추출기는 검출된 손을 좌우 라벨에 곧바로 대입했다. 두 손에 같은 라벨이 붙으면 좌표가 덮어써졌다. 좌우 라벨이 없는 검출도 `zip` 때문에 사라질 수 있었다.
- 학습은 최대 96프레임, 비교 화면은 48프레임만 검출기에 입력했다. 이 방식은 시간 추적기가 중간 프레임을 보지 못하게 했다.
- 기존 검사는 어느 손이든 보이는 프레임 수만 확인했다. 한쪽 손의 긴 누락을 별도로 점검하지 않았다.
- 기존 캐시는 특징 배열의 형태만 확인했다. 원본 영상과 추출 코드 변경 여부는 확인하지 않았다.
- 위치 증강은 손 존재 여부만 확인해서, 어깨 검출이 없는 프레임에도 몸 기준 손목 좌표를 만들 수 있었다. 몸 기준이 확인된 프레임에만 위치 증강을 적용하도록 수정했다.
- 실제 가림과 검출 실패도 있다. 접촉·겹침으로 보이지 않는 손가락은 재검출로도 항상 복원할 수 없다.
- 학습 환경의 실제 OpenCV는 4.14.0, 기존 Docker의 실제 OpenCV는 5.0.0이었다. `opencv-python`과 `opencv-contrib-python`의 공통 `cv2` 경로가 설치 순서에 따라 달라지는 구성이었다. 새 모델용 환경은 `opencv-contrib-python==4.14.0.94` 하나로 고정한다. 기존 모델 호환 배포에서는 원래 사용하던 실제 버전인 `opencv-contrib-python==5.0.0.93` 하나로 고정해 인식 입력을 보존한다.

MediaPipe의 좌우 라벨은 셀피처럼 좌우 반전한 입력을 가정한다.
현재 서비스는 반전하지 않은 원본 스트림을 처리하므로 기존 특징의 슬롯 순서를 유지하고,
Pose의 해부학적 손목과 대응할 때만 방향을 변환한다.
[MediaPipe 공식 문서](https://chuoling.github.io/mediapipe/solutions/hands.html#multi_handedness)

OpenCV 배포판은 하나만 설치해야 한다.
[OpenCV 패키지 공식 설치 안내](https://pypi.org/project/opencv-contrib-python/4.14.0.94/)
기존 호스트 Python은 실행 중인 추출 작업을 보존하기 위해 변경하지 않았다.
새 학습 환경은 별도 가상환경에서 `requirements-tracking.txt`로 구성한다.
`data/curriculum100_tracking_v2/environment.json`에 이번 실행의 실제 버전과 검출 모델 해시를 보존했다.

## 수정한 처리

`hand_tracking.py`가 검출 후보를 일대일로 배정한다. 손목의 신체 위치, 검출 라벨,
직전 프레임 위치를 함께 사용한다. 좌우 라벨이 같아도 서로 다른 검출을 덮어쓰지 않는다.
거의 동일한 중복 검출은 중복 제거하며, 두 개보다 많은 후보는 배정 비용으로 선택하고 초과 발생을 기록한다.

손목이 화면 안의 동작 영역에 보이는데 손 검출이 없으면 별도의 정지영상 검출기로
원본을 최대 960픽셀 폭으로 다시 확인한다. 기존 손과 중복되지 않고 신체 손목과 대응하는
실제 검출만 추가한다. 과거 손 모양 복사나 보간은 하지 않는다.

오프라인 추출은 원본 전체 프레임을 순서대로 처리한다. 프레임별 원시 손·신체 좌표,
154차원 특징, 시간, 원본 SHA256, 추출 코드 해시, 검출·재검출 기록을 함께 저장한다.
영상별로 추적 상태를 초기화한다. 원본 프레임 수와 저장한 프레임 수가 다르면 실패시킨다.

모델 입력은 기존과 같이 클립을 64프레임으로 시간 정규화한다. 이는 입력 길이를 맞추는
명시적인 선택 과정이며, 검출기에 중간 프레임을 보여주지 않거나 원시 데이터를 삭제하는 것과 구분한다.
시간 정규화 전의 전체 원시 좌표와 손 누락 표시는 별도로 남는다.

실시간 비교 좌표는 15fps 시간 격자와 새 손 배정·재검출 로직을 사용한다. 인식 입력은 체크포인트에 맞춰 별도로 선택한다.
반환 결과와 진단 기록에 추출 버전, 손별 검출 수, 예상되는 동작 손의 누락 지속 시간을 남긴다.
내려놓은 쉬는 손은 이 누락 검사에서 필수 손으로 취급하지 않는다.

## 데이터 감사와 학습

정면 영상 100단어 × REAL01~14 = 1,400개를 검사한다. 각 단어와 사람 조합이 정확히
한 번씩 있어야 한다. 원본 해시, 중복 영상, 시간 순서, 유한한 좌표, 손 존재 플래그와 좌표의
일치, 전처리·증강 후 누락된 손에 좌표가 생기지 않는지 검사한다.

몸의 손목으로 예상되는 손이 300ms 이상 연속 검출되지 않은 영상은 검수 후보로 남긴다.
Pose 자체도 추정이므로 이 표시는 양손이 반드시 필요한 단어라는 확정 판정이 아니다.
학습용 검수 후보는 삭제하거나 정답으로 보정하지 않고 분류 손실의 가중치를 절반으로 낮춘다.
원시 좌표와 증거는 계속 보존한다.

사람 분리는 기존과 같이 학습 REAL01~11, 검증 REAL12, 평가 REAL13~14이다.
정규화는 클립 내부 정보만 사용한다. 평가 사람의 좌표를 모범 영상으로 사용하지 않는다.
검수되지 않은 사용자의 연습 기록은 학습에 사용하지 않는다.

v7 실험은 기존 문맥 모델과 LSTM 분기를 새 좌표로 미세 조정했다.
반복 평가에서 기본 70단어의 정답은 137/140에서 136/140으로, 확신한 오답은 1건에서 2건으로
변해 배포하지 않았다. 기존 가중치에 수정된 입력만 넣는 방식도 같은 이유로 배포하지 않았다.

v8은 두 분기를 무작위 가중치에서 시작해 같은 학습 사람과 새 좌표로 처음부터 학습한다.
이 실험은 v7의 반복 평가 후 시작했다. 기존 평가 세트를 새 독립 평가라고 부르지 않는다.
별도로 이전 학습에 쓰지 않은 REAL15 영상 100개를 추출해 최종 평가에만 사용한다.
REAL15는 학습·모델 선택·온도 선택에서 제외하며, 모델 선택을 마친 뒤 한 번 평가한다.
기존 모델용 좌표도 이전 추출 방식으로 별도 만들어 같은 영상에서 비교한다.

v8은 반복 평가 70단어에서 139/140건을 맞혀 기존 137/140건보다 높았다.
그러나 REAL15의 70단어에서는 둘 다 68건을 맞혔고, 확신한 오답이 기존 0건에서 1건으로
늘었다. 짧은 입력의 확신한 오답 검사도 통과하지 못해 v8 가중치는 배포하지 않는다.

운영 배포는 기존 v5 가중치와 기존 검출 출력 형식을 유지한다. 동일한 1차 검출 결과에서
기존 모델용 좌표와 보완된 비교용 좌표를 따로 만든다. 새 좌표를 기존 가중치에 무조건 넣지 않는다.
실제 ‘미안하다’ 영상 71프레임에서 호환 입력과 기존 입력의 특징 차이는 0이었다.
비교 화면과 선택적인 자세 피드백은 보완된 좌표를 사용한다. 진단 파일의 `hands`는 실제
모델 입력이며 `corrected_hands`는 별도의 비교용 좌표다. 두 경로와 버전을 기록한다.
가중치가 바뀌지 않았다는 사실과 새 모델의 배포 보류 이유를 함께 보존한다.
모델 선택과 확률 결합·온도 선택은 REAL12에서만 한다. 평가 결과를 보고 재학습 설정을
다시 맞추지 않는다. 기존 v5의 원래 입력, 수정된 입력, v7의 수정된 입력을 비교한다.
모델에는 전처리 버전과 주요 라이브러리 버전, 정규화·손 배정·추출 코드의 AST 식별값을 기록한다.
서버의 실제 코드와 다르면 모델 로딩을 중단한다. 호스트와 서버 패키지의 코드 식별값 일치도 확인했다.
원본 입력 성능, 잘못 확신한 오답, 과정 밖 30단어 거부, 책상 가림과 짧은 입력을 확인한다.
배포 기준은 `tools/evaluate_tracking_v8.py`에 고정했다. 반복 평가와 새 인물 평가를 모두 확인한다.

REAL13~14는 프로젝트에서 반복 평가된 사람이다. 결과 수치는 실제 노트북 사용자 정확도나
새로운 사용자 전체에 대한 정확도를 뜻하지 않는다.

## 코칭과 배포

모범 좌표 210개도 동일한 원시 추출본에서 다시 만든다. 비교 화면 캐시는 원본 영상 해시와
설치된 추출 코드 해시가 일치해야 재사용한다. 모범 추적이 불안정한 경우에는 안정적인 다른
학습용 모범을 우선 선택한다. 모든 모범이 불안정하면 세부 교정을 생략하고 모범 영상의 가림을 안내한다.

단어 인식과 선택적인 자세 비교는 구분한다. 모범의 누락을 사용자의 잘못으로 안내하지 않는다.
수정 후에도 물리적 가림이나 검출기의 실패로 좌표가 남지 않는 구간은 발생할 수 있다.
그 구간은 없는 좌표로 유지하고 진단·검수 대상으로 기록한다.

Spring은 기존 Python 프록시를 통해 새 모델을 사용한다. 시험 녹화 방식과 학습 자동 녹화
시작·종료 조건은 변경하지 않는다. 배포 시 변경 전 해시를 확인하고 백업한 뒤 Python만 재시작한다.
상태 검사에 실패하면 백업으로 복구한다.

## 다시 실행

```powershell
$env:PYTHONDONTWRITEBYTECODE='1'
python tools/reextract_tracking.py --workers 4
python tools/audit_tracking.py
python train_tracking_v8.py
python tools/extract_tracking_actor15.py
python tools/evaluate_tracking_v8.py
python tools/prepare_tracking_references.py
python tools/deploy_tracking.py
```

현재처럼 새 가중치가 배포 기준을 통과하지 못한 경우에는 다음 명령으로 기존 인식 경로를
유지하며 코칭·비교·진단만 배포한다. 실패한 모델의 평가 결과나 배포 판정을 덮어쓰지 않는다.

```powershell
python tools/deploy_tracking.py --coaching-only
```

기존 데이터·실험은 보존한다. 추출 코드가 바뀌면 다른 해시 경로를 사용한다.
`train_tracking_v7.py`와 `train_tracking_v8.py`는 기존 실험 결과를 덮어쓰지 않는다.
이전 실험용 학습 스크립트의 옛 캐시는 새 모델 학습에 사용하지 않는다.

실제 영상 응답에서 진단의 NumPy 참·거짓 값이 JSON 변환을 실패시키는 문제도 발견해 기본 Python 자료형으로 바꾸고 회귀 검사를 추가했다. 최종 호스트·Docker 71개 검사와 실제 영상 요청에서 확인했다.
