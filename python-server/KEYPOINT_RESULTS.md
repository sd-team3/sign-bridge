> 현재 운영 상태: 사용자 요청으로 v8 테스트 적용. 인식·시험 판정은 v8 가중치와 hands_tracking_v2 전처리를 사용한다. 아래 배포 보류 설명은 이전 자동 검증 당시의 기록이며, 평가 결과 자체는 변경하지 않았다. v5 복구본을 별도 보존했다.

# 전처리·학습 전수 점검 결과

배포 선택: **기존 v5 가중치와 기존 인식 입력 유지. 코칭·비교·진단 및 새 학습 전처리만 개선.**
새 가중치 v7·v8은 각각 별도 보존했으며 배포 기준을 통과한 것으로 표시하지 않았다.
실제 배포 성공 여부와 설치 파일 해시는 `D:/sign-lang/tmp/tracking_deployment.json`에서 확인한다.

## 원인과 조치

- 같은 좌우 라벨이 붙은 두 손이 한 슬롯에 대입돼 덮어써지는 문제를 확인했다. 새 추출기는 검출 후보를 일대일로 배정한다. 라벨이 없는 검출도 버리지 않는다.
- 학습·비교용 추출에서 검출기에 중간 프레임을 보여주지 않던 방식을 전체 프레임 순차 처리로 바꿨다.
- 동작 영역에 손목이 보이는데 손이 검출되지 않으면 별도 영상 검출기로 확인한다. 신체 손목과 대응하고 기존 손과 중복되지 않는 실제 검출만 추가한다.
- 손별 누락, 코드 버전, 원본 해시를 확인하지 않던 검사를 보완했다. 원시 좌표로 특징을 다시 만들고 저장된 특징과 대조했다.
- 어깨 검출이 없는 프레임에 위치 증강이 몸 기준 손목 좌표를 만들던 문제를 수정했다.
- OpenCV 배포판 중복 설치를 해소했다. 기존 인식 호환 모드에서는 기존 실제 버전 5.0.0을 유지한다. 새 모델용 환경은 4.14.0으로 고정했다.

## 데이터 검사

- 100단어 × 14명 = **1,400개 영상 / 166,986프레임**. 원본 프레임을 모두 보존했고 중복 원본·누락 조합·비유한 좌표 검사를 통과했다.
- 좌우 라벨 충돌 **2,926프레임**, 별도 재검출로 추가된 손 **5,806개**.
- 이전과 같은 시점으로 맞춰 비교한 검출 손 슬롯은 **253,308 → 263,519개**. 이 수치는 정답 검출률이나 분류 정확도를 뜻하지 않는다.
- 긴 누락 검수 후보 **53개**. 학습용 46개는 분류 손실 가중치를 낮췄다. 가려진 손가락을 복사하거나 보간하지 않았다.
- 원시 좌표와 특징의 일치 검사, **4,200회 증강 검사** 통과.
- 쉬는 손 제외와 두 손의 근접 상호작용이 겹치는 검수 후보는 **0개**였다. 미안하다의 손을 쉬는 손으로 통째로 제외한 사례도 없었다.
- 모범 영상 **210개** 모두 학습 원본과 파일 해시가 일치했다. 새 좌표·아바타 캐시 210개를 만들었다. 추적 검수 모범 7개는 안정적인 다른 모범을 우선 선택한다. 모든 단어에 안정적인 모범이 하나 이상 있다.

## 학습과 평가

학습 REAL01~11, 검증 REAL12, 반복 평가 REAL13~14를 분리했다.
사용자 연습의 목표 단어를 검증된 정답으로 간주해 학습하지 않았다.

| 모델·입력 | 반복 평가 정답 / 140 | 확신한 오답 |
|---|---:|---:|
| 기존 v5·기존 입력 | 137 | 1 |
| 기존 v5·새 입력 | 136 | 2 |
| v7 미세조정·새 입력 | 136 | 2 |
| v8 처음부터 학습·새 입력 | 139 | 1 |

v8은 84회차까지 학습했고 검증 손실로 59회차를 선택했다. 최종 검증에서 문맥 모델 단독,
온도 0.8을 선택했다. 기존 14명 평가는 프로젝트에서 반복 사용된 평가이며 독립 사용자 연구가 아니다.

이전 학습에 사용하지 않은 REAL15 영상 100개를 별도 추출했다. 모델 선택 후 한 번 평가했고,
이 사람을 학습·온도 선택에 사용하지 않았다. 기존 14명 원본과 중복 파일도 없었다.

| 모델 | 새 인물 정답 / 70 | 확신한 오답 | 전체 정답 / 100 |
|---|---:|---:|---:|
| 기존 v5 | 68 | 0 | 97 |
| v8 | 68 | 1 | 98 |

v8은 반복 평가에서 개선됐지만 새 인물의 확신한 오답과 짧은 입력의 확신한 오답 검사에서
기준을 통과하지 못했다. 평가 결과에 맞춰 모델·임계값을 다시 조정하거나 배포 판정을 바꾸지 않았다.

## 운영 호환과 검증

기존 모델 입력은 1차 손 검출 결과의 기존 출력 형식을 보존한다. 비교 화면과 선택적인 자세
피드백에는 보완된 좌표를 사용한다. 실제 미안하다 영상 71프레임에서 기존 입력과 호환 입력의
최대 특징 차이는 **0**이었다. 보완된 좌표를 기존 가중치에 무조건 넣는 방식은 사용하지 않는다.

진단 파일의 `hands`는 실제 모델 입력이다. `corrected_hands`는 별도의 비교용 좌표다.
코드·라이브러리가 맞지 않는 새 체크포인트는 로딩을 중단한다.

배포 전 Python 서버 70개 테스트, 루트 전처리 23개 테스트, Spring Java 46개 검사와
시험 UI·자동 녹화·비교 화면 검사를 통과했다. 배포 후 호스트 71개·Docker 71개(환경 전용 1개 생략) 검사를 통과했다. 실제 영상 POST는 정상 응답했고 미안하다로 인식했다. 중간 이미지에는 손바닥 표시 8개(모범/사용자 각 양손과 확대)가 있고 미검출 표시는 0개였다. Spring 프록시와 지문자 31개 클래스 상태도 정상이다. 진단 NumPy 값의 JSON 직렬화 오류는 실제 요청에서 발견해 수정하고 회귀 검사로 확인했다.
시험의 수동 녹화 방식, 단어 학습의 자동 녹화 시작·종료 조건, 기존 가중치와 판정 기준은 유지한다.

물리적인 가림과 검출 실패가 완전히 없어졌다는 의미는 아니다. 남는 누락은 기록·검수하며
없는 손 모양을 만들어 내지 않는다. 기존 모델의 원래 입력 방식도 호환을 위해 남아 있다.
새 가중치의 운영 적용은 보류했으며, 새 좌표 데이터와 두 실험 결과는 다음 개선에 사용할 수 있다.

추가 확인: 저장한 실제 요청의 모델 입력 71프레임을 재생했을 때 예측 점수 차이는 0이었다. 데스크톱 단일 영상 인식 도구도 기존 모델 호환 경로에서 미안하다로 인식했다. 테스트 촬영 기록은 자동 테스트로 표시해 사용자 연습과 구분했다.
